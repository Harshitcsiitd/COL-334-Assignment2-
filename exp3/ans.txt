xperiment 3: Report AnswerQuestion: What does a non-blocking recv() return when reading an incomplete application message, and how does the server handle it?
Answer: TCP guarantees an ordered, reliable byte stream but preserves neither the sender's write boundaries nor any concept of an application message. When a non-blocking recv() reads an incomplete message, it simply returns however many bytes are currently available in the kernel socket buffer. Any subsequent immediate read on that empty buffer returns -1 with errno 35 (EAGAIN / Resource temporarily unavailable). Because message framing is purely an application responsibility, the server handles this by accumulating the returned bytes into a per-connection LineBuffer in userspace. The server only attempts to extract and process an order when it scans this buffer and finds a complete \n delimiter.  Approach:
To prove that message boundaries exist only in the application, the proof was made on both sides of the boundary simultaneously. The Python harness was configured to write a single 24-byte message using four separate send() calls spaced 0.2 seconds apart. tcpdump captured the four discrete TCP segments on the wire, and ktrace captured the server executing four distinct recvfrom() calls, each ending in EAGAIN.
